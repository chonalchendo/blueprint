## Problem

A body changes only by hand, outside the write path. 13 says an active design changes only through an accepted delta, and nothing enforces it.

## Shape

`set <id> --body-file <f>` replaces the body and keeps the header byte for byte. The body passes the same normalising and check rules as `create`. A design that is not `draft` refuses `design_not_delta`, with a fix naming `record delta`. The same body exits 3.

"Trailing whitespace" means the end of the body only, so a Markdown hard break inside it is a change. The new body is LF in every file. A body file that starts with a header (a `---` block whose YAML holds `kind`) refuses `schema_invalid`, so a node's own file cannot nest its header. A dry run refuses what the write refuses, `path_dirty` included, and shows the stored body.

## Check

~~~check shell {name=set-body expect=0}
cargo build --release -p bp-tool; B=${CARGO_TARGET_DIR:-$PWD/target}/release/bp; D=$(cargo xtask scratch); export BP_VAULT=$D; g() { git -C $D "$@"; }
I=projects/bp/issues/0413.land-verification-has-no-timeout; F=$(mktemp); H=$(mktemp)
awk 'NR == 1 || !e { print } NR > 1 && /^---$/ { e = 1 }' $D/$I.md > $H
printf 'A new body for quokka.\n' > $F
$B set $I --body-file $F --json | jq -e '.commit'
awk 'NR == 1 || !e { print } NR > 1 && /^---$/ { e = 1 }' $D/$I.md | diff - $H
$B show $I --json | jq -r .body | diff - $F
rc=0; $B set $I --body-file $F --json > /dev/null || rc=$?; test $rc -eq 3
$B set $I --body-file $D/$I.md --json | jq -e '.code == "schema_invalid"'
$B search quokka --json | jq -e --arg i $I '.rows[0].id == $i'
test "$(g rev-list --count HEAD)" -eq 2
~~~
