## Problem

No verb claims an issue. The 1,703 converted claims came from today's `cut`, which leaves the issue's status (21, check 2).

## Shape

Design changes 2, 6 and 7. `cut <issue> [--base]` refuses `illegal_transition` unless the issue is `open`, and `path_dirty` on a dirty issue file. It fetches, adds the worktree and branch, then commits the claim and the status. A failed commit removes the worktree and the branch. `cut` reuses a kept worktree for the branch, and adds one for a kept branch whose worktree is gone; a repeat puts a removed worktree back, then exits 3. `release <issue> --reason <escalated|dropped|lost>` appends `## Released` with `to` and `reason`, moves the issue to `open` and keeps the worktree. With no active claim it exits 3. The check runner strips `BP_SESSION` from a block, as it strips `BP_NOW` and `BP_ROLE` (`bp-check/src/process.rs`). Issue 5 adds `depends`.

## Design changes

2. **Where the repo verbs act** (15, Interfaces; 03, `repository`). A repo verb runs in a clone of the project repository (`where`); elsewhere it refuses `no_clone` (exit 2), and the fix names the repository url. The branch is `<project>/<slug>`; the worktree is `<top>/../<name>-worktrees/<slug>`, canonical. `<top>` is the main worktree of the clone (the parent of git's common directory), so a run inside a linked worktree does not nest. `cut` fetches and cuts from `origin`'s default branch, or from `--base`. It records the base branch, the origin branch `--base` names or else the default, and `pr` targets it. A repo verb does its network step with no lock held; it checks its preconditions before and again under the lock, as `stamp` does around its blocks. Additive: one code.
6. **One commit per verb, runs included** (12, Interfaces 3). `pr`, `land` and `stamp` commit their run records with their own changes; `pr` adds no third trailer. `bp-check` splits into a run with no lock and the record text. Not a contract change.
7. **Claim fields at the verbs** (13, Claim). `cut` writes `from`, `owner` from `BP_ROLE`, `session` from `BP_SESSION`, `worktree`, `base`, `base_branch` and `base_issue`. `pull_request` moves to the closing append, because the number appears only at `pr`; the forge finds it by branch (15). A repeat `cut` with the same owner and session exits 3; any other active claim refuses `already_claimed`. Until milestone 4 puts a dispatch id in `BP_SESSION`, a session dispatches at most one worker per issue. `cut` does not refuse an escalated issue: the new claim is the answer, and the escalation ends (21, blocked). `release` writes `to` and `reason` and no cost fields; the harness is their source (13, Claim). No verb refuses by role, because an agent can unset `BP_ROLE` (25, design change 7). Additive: one environment value.

## Check

~~~check shell {name=cut-and-release expect=0}
cargo build --release -p bp-tool -p xtask; B=${CARGO_TARGET_DIR:-$PWD/target}/release/bp; D=$(cargo xtask scratch); export BP_VAULT=$D; g() { git -C $D "$@"; }
T=$(cargo xtask forge bp); export PATH=$T/bin:$PATH GIT_ALLOW_PROTOCOL=file; test "$(command -v gh)" = $T/bin/gh
S=projects/bp/designs/system; U=projects/bp/milestones/cut-milestone; I=projects/bp/issues/cut-quokka; R=projects/bp/issues/0407.the-artifact-model-and-integrity-checks
$B create milestone --project bp --title "Cut milestone" --under $S --json > /dev/null; $B transition $U approved --json > /dev/null
$B create issue --project bp --title "Cut quokka" --under $U --json > /dev/null
intent() { $B list issue --project bp --json --limit 2000 | jq -r --arg i $I '.rows[] | select(.id == $i) | .intent'; }
cd $T/code; echo >> $D/$I.md; $B cut $I --json | jq -e '.code == "path_dirty"'; g checkout -q -- $I.md
W=$($B cut $I --json | jq -r .worktree); test -d $W
rc=0; $B cut $I --json > /dev/null || rc=$?; test $rc -eq 3
BP_SESSION=other $B cut $I --json | jq -e '.code == "already_claimed"'
$B cut $R --json | jq -e '.code == "illegal_transition"'
test "$(intent)" = working
$B release $I --reason escalated --json | jq -e '.commit'; test -d $W
g log -1 --format=%B | grep -qx 'Bp-Verb: release'
$B show $I --json | jq -e '.status == "open"'; test "$(intent)" = blocked
rc=0; $B release $I --reason dropped --json > /dev/null || rc=$?; test $rc -eq 3
rc=0; $B release $I --reason sideways --json > /dev/null || rc=$?; test $rc -eq 4
$B set $I severity low --json | jq -e '.commit'; test "$(intent)" = ready
$B cut $I --json | jq -e --arg w $W '.worktree == $w'
test "$(command ls $D/$I/claims | wc -l)" -eq 2
test "$(g rev-list --count HEAD)" -eq 8; test "$(git worktree list | wc -l)" -eq 2
~~~
